# Visual Compression

## Purpose

Use visual compression when a brief becomes clearer as a table, timeline, scorecard, or before/after view.

This is still Smart Brevity. The goal is faster understanding, not richer formatting.

## When To Use

Use a compact visual structure when the source contains:

- multiple options to compare
- dates, milestones, or rollout phases
- risks, owners, or decision points
- metrics that should be scanned together
- old state vs new state
- noisy prose that can become a simple table

Skip visual compression when:

- a short bullet is clearer
- the table would have only one meaningful row
- the structure hides nuance the reader needs
- the brief is public-facing and the table would feel too operational

## Useful Forms

| Communication Need | Best Form |
|---|---|
| Compare options | 3-5 row decision table |
| Show schedule | timeline or dated bullet list |
| Show metrics | small "By the numbers" block |
| Show accountability | owner/action/date table |
| Show tradeoffs | risk/impact/mitigation table |
| Show change | before/after table |
| Show reader action | "What you need to do" checklist |

## Rules

- Lead with the news before the table.
- Keep tables small enough to scan in a few seconds.
- Use plain labels, not clever headings.
- Put the most important column first after the item name.
- Do not include columns that are mostly empty or repetitive.
- Keep caveats visible when they affect the decision.
- Prefer bullets over tables when there are fewer than three comparable items.

## Quality Check

Before returning the brief, ask:

1. Does this structure make the signal faster to see?
2. Can the reader understand the point without reading every cell?
3. Did we preserve the important risk, date, owner, or decision?
4. Would a bolded bullet be simpler?

If the visual structure fails this check, collapse it back into Smart Brevity bullets.
