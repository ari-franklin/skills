# Visual Storytelling

## Purpose

Use visual storytelling to make the post's argument easier to notice, feel, understand, and remember.

Visuals should clarify the article's tension, sequence, structure, or practical implication. They are not decoration, brand garnish, or proof that the post is polished.

## Core Principle

Start with:

```text
audience -> point -> story sequence -> visual job -> visual form
```

Do not start with a chart type, diagram type, or image style.

## Visual Story Jobs

| Article Need | Useful Visual |
|---|---|
| Make the opening tension concrete | editorial hero image, scene image, before/after image |
| Explain a system or relationship | Mermaid diagram, dependency map, simple flow |
| Show a change over time | timeline, lifecycle, before/after sequence |
| Compare old belief vs better belief | two-column table, paired panels |
| Show a decision rule | callout block, decision tree, compact table |
| Make a mental model memorable | grounded metaphor image or simple diagram |
| Help a reader apply the post | checklist, decision test, practical table |

## Story Sequence

A strong visual story usually follows this sequence:

1. Context: what situation is the reader in?
2. Tension: what is confusing, costly, or commonly misunderstood?
3. Pattern: what structure explains the tension?
4. Turn: what changes when the reader sees it this way?
5. Action: what should the reader do differently?

Use visuals at the points where the reader would otherwise spend extra effort reconstructing the structure, sequence, or relationship in the idea.

## Selection Rules

- Use images to make a tension felt.
- Use diagrams to make a structure visible.
- Use tables to make a comparison scannable.
- Use timelines to make sequence and change legible.
- Use callouts to make a practical test easy to apply.
- Use charts only when quantitative evidence is central and the chart type matches the analytical job.
- When the prose needs many examples, roles, or factors to close the argument, consider whether they form a chain, dependency map, lifecycle, or table. Visualize that relationship only if it reduces reader effort.

Chart shortcuts:

| Data Question | Better Starting Point |
|---|---|
| Which is larger? | bar, column, dot plot |
| What changed over time? | line chart, timeline, annotated trend |
| How is this distributed? | histogram, box plot |
| How are two things related? | scatter plot |
| What contributes to the whole? | stacked bar or treemap; pie only for a few obvious parts |
| How does something flow? | Sankey, funnel, flowchart |

## Quality Check

Before adding a visual:

- The thesis is stable enough to visualize.
- The visual has one clear job.
- The reader knows what to look at first.
- The visual does not introduce a new unsupported claim.
- The visual can be understood without decorative complexity.
- The post still works if the visual fails to render, unless the user specifically asked for a visual-first artifact.

## Anti-Patterns

- Adding a diagram because the article feels thin.
- Using a generic hero image that could fit any productivity post.
- Turning every section into a visual device.
- Choosing a clever metaphor that weakens the practical argument.
- Using motion, interaction, or HTML layout to hide a weak thesis.
- Making uncertainty visually disappear.
