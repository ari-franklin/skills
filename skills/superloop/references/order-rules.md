# Order Rules

## Purpose

Determine the sequence of reasoning modes.

The goal is not to execute every mode.

The goal is to close reasoning gaps in the correct order.

## Rule 0

If the reasoning gap is unclear:

Explain first.

If the reasoning gap is clear:

Start with the mode that directly closes that gap.

## Rule 1

Do not prioritize what is not understood.

Understanding before decisions when understanding is missing.

Bad:

Prioritize -> Explain

Good when the option set is unclear:

Explain -> Prioritize

Good when the options and decision frame are already clear:

Prioritize

## Rule 2

Do not decompose what is undefined.

Understanding before structure when the object is undefined.

Bad:

Decompose -> Explain

Good when the object is unclear:

Explain -> Decompose

Good when the target is already defined:

Decompose

## Rule 3

Do not validate unstated claims.

Make the claim explicit first. If the claim is already explicit, Validate can be the first mode.

Bad when the claim is fuzzy:

Validate

Good when the claim needs clarification:

Explain -> Validate

Good when the claim and evidence are already stated:

Validate

## Rule 4

Decision before structure.

When selecting among clear options:

Prioritize -> Decompose

When the options themselves are unclear:

Explain -> Prioritize -> Decompose

Reason:

There is little value in decomposing work that may not be selected.

## Rule 5

Structure before prioritization.

When the object itself is unclear:

Explain -> Decompose -> Prioritize

When the object is clear but large:

Decompose -> Prioritize

Reason:

You cannot rank parts of a system until the useful parts are visible.

## Rule 6

Validation before commitment.

The larger the commitment, the stronger the validation requirement.

Good when the priority frame is already clear:

Prioritize -> Validate

Good when the priority frame is unclear:

Explain -> Prioritize -> Validate

Use this before major investment or execution.
