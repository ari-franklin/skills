# Visual Reasoning

## Purpose

Use visual reasoning when a Superloop output would be easier to understand as a shape, sequence, comparison, or relationship.

This is an explanation aid, not a separate reasoning mode. The visual form must follow the reasoning. Do not select a chart, diagram, or artifact before the claim, audience, and decision are clear.

## When To Use

Consider a visual layer when the answer contains:

- a sequence of steps, events, or decisions
- a comparison among options
- a hierarchy, system, or decomposition
- a causal chain or assumption chain
- a priority ranking
- a before/after change
- a relationship map among teams, dependencies, risks, or outcomes

Skip the visual layer when:

- the answer is already simple enough in prose
- the visual would add decoration without reducing effort
- the underlying reasoning is still weak or ambiguous
- the visual would hide uncertainty or make evidence look stronger than it is

## Visual Jobs

Choose the visual job before choosing the visual form.

| Reasoning Need | Useful Form |
|---|---|
| Explain a route or sequence | timeline, flowchart, route map |
| Compare options | table, ranked list, 2x2 only when axes are meaningful |
| Show hierarchy or decomposition | tree, nested list, mindmap |
| Show dependencies or causal logic | flowchart, dependency map, assumption chain |
| Show evidence strength | table with evidence grade, confidence, and caveats |
| Show decision tradeoffs | options table, risk/benefit grid |
| Show what changed | before/after table or paired flow |

## Visual Story Check

Before adding a visual element, answer:

1. What decision, understanding, or action should this visual improve?
2. What should the reader notice first?
3. What can be removed without harming the point?
4. What uncertainty must remain visible?
5. Could a simpler table or annotated list do the job?

## Guardrails

- A good visual reduces effort without reducing truth.
- Preserve the same reasoning and uncertainty as the text.
- Make the important thing visually obvious.
- Use labels and annotations instead of relying on color alone.
- Prefer simple tables, timelines, and route maps before complex diagrams.
- Do not add visual storytelling to make a weak recommendation feel stronger.
